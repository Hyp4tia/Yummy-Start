# Task title

This is a reusable template, not an active task. Copy it only when there is real,
authorized work to record. Use the existing task system instead when appropriate.

- **ID:** Not set; choose an ID unique within the project and keep it stable.
- **Status:** Not set; choose queued, active, or completed. Use the matching folder.
- **Owner:** Unknown; record a person or agent only when actually assigned.
- **Area:** Not established; link to the relevant area or state not applicable.

## Intended outcome

Describe the observable result and link to the relevant project goal.

## Completion criteria

List what must be true, and how it will be checked, before marking this completed.
Criteria are not evidence of completion; record the checks below when performed.

## Current progress

Record verified progress, with sources where useful. Do not repeat the full
project status or copy decision rationale here; link to those owning documents.

## Next action

State one concrete next step. For completed tasks, state none or a separately
tracked follow-up; do not hide unfinished required work behind completed status.

## Blockers

Record known blockers, who or what can resolve them if known, or none confirmed.

## Task-specific user instructions

Record direct corrections or requirements limited to this task, with a short
source quote or paraphrase and their scope. A task-specific exception does not
replace a lasting project rule. Link to applicable lasting rules in `AGENTS.md`
instead of copying them. Do not promote ambiguous feedback to a permanent rule.

## Sources and decisions

Link to inputs, existing work, and relevant entries in `DECISIONS.md`.

## Deliverables

Link to each actual artifact and label its readiness: draft, review-ready, or
finished. Deliverables normally belong in the project's outputs folder. Link to
code or other artifacts at their required existing paths; do not duplicate them.
If this task produces no artifact, state that explicitly.

## Completion evidence

For completed tasks, record checks against the criteria, result, and evidence.
Record completion date and reviewer only when known. Completion records stay
in the completed task folder even when the resulting artifact lives elsewhere.
